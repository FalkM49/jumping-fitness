# Этап 4. Cloud Functions: бизнес-логика

Вся защита от нечестной игры и логических ошибок (ТЗ 8) живёт здесь, в `functions/src/`.
Работают функции в **Yandex Cloud** (раздел «Yandex Cloud» в конце); тот же код
проверяется тестами в эмуляторе Firebase и через переходник Yandex.
Приложение только вызывает функции и показывает результат. Прямая запись в места,
тренировки на счету, сроки и роли запрещена правилами Firestore.

Общее для всех функций:

- **Вызов**: `callableFor(regionalFunctions(), имя).call(аргументы)` (`lib/services/cloud_functions.dart`):
  в Yandex Cloud — `httpsCallableFromUrl('<адрес шлюза>/<имя>')`, в эмуляторе — `httpsCallable(имя)`.
- **Кто вызывает**: роль читается из `users/{uid}` на сервере. Что прислал телефон, не важно.
- **Время**: только серверное. «Сегодня» — день по Москве (UTC+3).
- **Атомарность**: всё, что меняет места, счёт тренировок и статусы записей, выполняется
  в одной транзакции. Одновременные нажатия не дают 14/13 и не списывают тренировку дважды.
- **Отказ по правилу**: код `failed-precondition`, в `message` готовый текст по-русски,
  в `details.reason` машинная причина (таблица ниже). Для кнопки «Записаться» из `reason`
  берётся текст для значка (i) (ТЗ 3.1).
- **Ошибки ввода**: `invalid-argument` с понятным текстом. Без входа — `unauthenticated`,
  нет прав — `permission-denied`, нет документа — `not-found`.
- **Уведомления** (этап 7): `sendNotification(...)` в `functions/src/notifications.ts`.
  Сбой уведомления не отменяет уже выполненное действие. Подробности — в разделе
  «Уведомления» ниже.

## Функции

### Клиент

| Функция | Аргументы | Что делает | Возвращает |
|---|---|---|---|
| `bookTraining` | `{ trainingId }` или `{ date, slot }` | Запись на тренировку. `{ date, slot }` — для тренировки по расписанию, которой ещё нет в базе: её документ создаётся этой же записью | `{ trainingId, bookedCount, trainingsLeft }` |
| `cancelBooking` | `{ trainingId }` | Отмена своей записи строго раньше чем за 3 ч до начала. Тренировка возвращается на абонемент | `{ trainingId, refunded }` |
| `freezeSubscription` | `{ days }` | Заморозка текущего абонемента с сегодняшнего дня на `days` дней | `{ subscriptionId, freeze, endDate }` |
| `notifyTrainerRequest` | — | Сообщить администраторам о своей только что поданной заявке в тренеры. Приложение вызывает сразу после регистрации. Повторно не шлёт (отметка `adminsNotifiedAt`) | `{ notified }` |
| `ensureMonthlyFlower` | — | Цветок месяца для себя, если на текущий месяц его ещё нет (добавлена на этапе 5). Не повторяет цветки двух предыдущих месяцев (ТЗ 4) | `{ month, flowerId }` |

Проверки `bookTraining` (все одновременно, ТЗ 3.1):
- абонемент текущий, свой и действует сегодня;
- дата тренировки в пределах срока абонемента;
- не идёт заморозка;
- на счету больше 0 тренировок;
- есть свободное место;
- тренировка не началась и не отменена;
- тренер не удалял клиента с этой тренировки.

Тренер записываться не может.

### Тренер и администратор

| Функция | Аргументы | Что делает | Возвращает |
|---|---|---|---|
| `createTraining` | `{ date, slot, startTime?, durationMinutes?, capacity? }` | Новая тренировка в пустой ячейке («+»). Не переданные значения берутся из `settings/defaults` | `{ trainingId }` |
| `updateTraining` | `{ trainingId }` или `{ date, slot }` и хотя бы одно из `startTime`, `durationMinutes`, `capacity` | Правка тренировки. Мест не меньше, чем записано. Время остаётся в своей строке. При смене времени или длительности уведомляются записанные | `{ trainingId, notifiedClients }` |
| `cancelTraining` | `{ trainingId }` или `{ date, slot }` | Отмена: всем записанным тренировка возвращается, им уходит уведомление | `{ trainingId, refundedClients }` |
| `removeClientFromTraining` | `{ trainingId, clientId }` | «Мусорка»: клиент удалён, тренировка возвращена, место свободно. Записаться на эту же тренировку клиент больше не сможет. Клиенту уходит уведомление | `{ trainingId, clientId }` |
| `renewSubscription` | `{ clientId, startDate, endDate, trainings, freezeLimitDays }` | Новый абонемент клиенту. Старый остаётся в истории (`isCurrent: false`, `closedAt`), заморозка снова доступна | `{ subscriptionId, previousSubscriptionId }` |

### Только администратор

| Функция | Аргументы | Что делает |
|---|---|---|
| `approveTrainerRequest` | `{ uid }` | Заявка → approved, роль → trainer, уведомление заявителю |
| `rejectTrainerRequest` | `{ uid }` | Заявка → rejected |
| `runSubscriptionExpiry` | — | То же, что ночная проверка сроков, но сейчас (на случай сбоя планового запуска) |

### По расписанию

| Функция | Когда | Что делает |
|---|---|---|
| `assignMonthlyFlowers` | в Yandex — каждую ночь в 00:10 МСК (меняет цветок только в новом месяце); в Firebase — 1-го числа в 00:10 | Всем пользователям — цветок нового месяца, не повторяя цветки двух предыдущих (ТЗ 4) |
| `expireSubscriptionsDaily` | каждый день в 00:05 по Москве | Текущие абонементы, у которых последний день прошёл: тренировки сгорают (`trainingsLeft → 0`, сколько сгорело — в `burnedTrainings`), ставится `expiredAt`, клиенту уходит уведомление (ТЗ 5 п. 3). Повторный запуск ничего не меняет |

## Причины отказа (`details.reason`)

| reason | Когда |
|---|---|
| `no_training` | В ячейке нет тренировки (пусто, или тренировку по расписанию отменили) |
| `training_cancelled` | Тренировка отменена |
| `training_started` | Тренировка уже началась (запись, правка, отмена) |
| `already_booked` | Клиент уже записан |
| `removed_by_trainer` | Тренер удалил клиента с этой тренировки — повторная запись запрещена |
| `trainer_cannot_book` | Записаться пытается тренер |
| `no_subscription` | Нет текущего абонемента |
| `subscription_not_started` | Абонемент начнётся позже |
| `subscription_expired` | Срок абонемента истёк |
| `outside_subscription` | Тренировка позже окончания абонемента |
| `frozen` | Идёт заморозка |
| `no_trainings_left` | На абонементе 0 тренировок |
| `full` | Нет свободных мест |
| `not_booked` | Отменить или удалить нечего — записи нет |
| `cancel_window_passed` | До начала 3 часа или меньше — отмена недоступна |
| `slot_taken` | В ячейке уже есть тренировка |
| `slot_has_default` | В ячейке тренировка по расписанию: её надо изменить, а не создавать новую |
| `in_past` | Время тренировки уже прошло |
| `capacity_below_booked` | Мест меньше, чем записано. Число записанных есть в тексте |
| `already_cancelled` | Тренировка уже отменена |
| `subscription_inactive` | Заморозить можно только действующий абонемент |
| `freeze_used` | Заморозка в этом периоде уже была |
| `freeze_unavailable` | Лимит заморозки 0 |
| `freeze_limit` | Дней больше лимита |
| `not_client` | Абонемент оформляется только клиенту |
| `ends_in_past` | Абонемент закончился бы в прошлом |

## Как рисовать отменённую тренировку (для этапов 5–6)

После `cancelTraining`:

- документ тренировки остаётся со `status: 'cancelled'`, это история;
- ячейка `calendar_slots` получает `activeTrainingId: null, overridesDefault: true`;
- у всех, кто был записан, запись получает статус `training_cancelled`.

Отсюда:

- **Тренер** видит пустую ячейку («+») и может сразу назначить новую тренировку.
  Тренировка по расписанию в этот день больше не появляется.
- **Клиент, который был записан**, видит «Отменено», если в ячейке пусто, а у него есть
  запись `training_cancelled` на этот день и строку. Если тренер поставил в ячейку новую
  тренировку, клиент видит её и может на неё записаться.
- **Остальные клиенты** видят обычную пустую ячейку.

## Уведомления (этап 7)

Каждое уведомление уходит по двум каналам (ТЗ 5):

1. **История в приложении** — `users/{uid}/notifications/{id}`: `kind`, `title`, `body`, `data`,
   `read`, `createdAt`. Хранятся последние 50. Экран «Уведомления» (колокольчик в шапке
   со счётчиком непрочитанных) показывает их, даже если push пропущен. Правила разрешают
   пользователю только читать свои и отмечать их прочитанными.
2. **Push через FCM** на все устройства из `users/{uid}/devices`. Токены, которые FCM
   признал недействительными, удаляются. В эмуляторе push не отправляется: у эмулятора
   нет FCM, история при этом пишется.

| `kind` | Кому | Когда |
|---|---|---|
| `training_changed` | записанным | Тренер изменил время или длительность (ТЗ 3.2) |
| `training_cancelled` | записанным | Тренер отменил тренировку (ТЗ 3.2) |
| `removed_from_training` | клиенту | Тренер удалил с тренировки (ТЗ 3.2) |
| `subscription_ending_soon` | клиенту | Осталось 5 дней или меньше — один раз за период, ежедневная проверка (ТЗ 5 п. 1) |
| `subscription_low_trainings` | клиенту | После записи осталась 1 тренировка — один раз за период (ТЗ 5 п. 2) |
| `subscription_expired` | клиенту | Срок истёк, тренировки сгорели (ТЗ 5 п. 3, 8.5) |
| `trainer_request_new` | администраторам | Подана заявка в тренеры — `notifyTrainerRequest` от приложения (в Firebase также триггер `onTrainerRequestCreated`; уведомление одно) (ТЗ 2) |
| `trainer_request_approved` / `_rejected` | заявителю | Решение администратора (ТЗ 2) |

`data` в push и в истории: `kind` и то, что нужно для перехода по тапу. Для тренировок это
`trainingId`, `date`, `slot`: тап открывает окно этой ячейки календаря. Заявка открывает
экран заявок (администратору), уведомление об абонементе — главный экран.

## Решения, принятые на этом этапе

Все шесть подтверждены заказчиком (26.09.2026).

1. **Куда вернуть тренировку.** В абонемент, с которого её списали, если он ещё текущий.
   Иначе в текущий абонемент клиента. Если выбранный абонемент уже истёк по сроку,
   возврат идёт в `burnedTrainings`, а не «висит» на счету, которым нельзя воспользоваться.
2. **Заморозка** начинается сегодня, дата окончания абонемента сдвигается сразу на все дни.
   Итог тот же, что при сдвиге на +1 за каждый день (ТЗ 5).
3. **Граница утра и вечера** — 14:00: утренняя тренировка начинается раньше 14:00,
   вечерняя — с 14:00. Правка не переносит тренировку в другую строку.
4. **Записаться** можно только на тренировку в пределах срока абонемента. Иначе клиент
   списал бы тренировку, которую не сможет посетить.
5. **Удалить клиента** тренер может в любой момент, в том числе после начала. Правило
   3 часов относится только к отмене самим клиентом.
6. **Остаток старого абонемента** при продлении не переносится. Тренер сам задаёт
   количество тренировок нового периода (ТЗ 6).

## Yandex Cloud (согласованная замена Firebase Cloud Functions)

Google Cloud не принимает новых клиентов из России, поэтому тариф Blaze (без него
Firebase не выкладывает функции) недоступен. Функции работают в Yandex Cloud Functions;
Firebase — на бесплатном Spark (база, вход, push).

- **Переходник** `functions/src/yandex.ts` (обработчик `lib/yandex.handler`): переводит
  HTTP-запрос Yandex в вызов тех же функций (`onCall(...).run()`) и отвечает по протоколу
  callable Firebase — `{ result }` или `{ error: { status, message, details } }`. Поэтому
  приложение вызывает их тем же плагином `cloud_functions`, коды ошибок и `details.reason`
  не меняются. Вход — ID-токен Firebase Auth, проверяется `verifyIdToken`.
- **API Gateway** перед функцией: при прямом вызове функции Yandex сам разбирает заголовок
  `Authorization` как свой IAM-токен (403). Шлюз передаёт заголовок как есть и вызывает
  функцию от сервисного аккаунта; напрямую функция закрыта.
- **Таймеры** Yandex (по UTC): `5 21 ? * * *` → `expireSubscriptionsDaily`,
  `10 21 ? * * *` → `assignMonthlyFlowers`; имя задачи — в `payload`.
- **Доступ к Firebase** — ключ сервисного аккаунта из секрета Lockbox в переменной
  `FIREBASE_SERVICE_ACCOUNT` (`index.ts`).
- **Триггеров Firestore** в Yandex нет: уведомление о новой заявке шлёт `notifyTrainerRequest`.
- **Выкладка**: `cd functions` → `npm run deploy:yc` (скрипт `scripts/deploy-yandex.mjs`).
- **Локально**: `npm run dev:api` — переходник как HTTP-сервер на `127.0.0.1:5002` поверх
  эмуляторов; приложение: `--dart-define=FUNCTIONS_API_URL=http://10.0.2.2:5002`.
