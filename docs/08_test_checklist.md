# Этап 8. Чек-лист тестирования

Проверка идёт в два слоя.

1. **Автотесты на эмуляторах Firebase.** Проверяют серверную логику и правила ровно
   так, как будет в облаке: те же функции и тот же `firestore.rules`. Прогнаны
   27.09.2026 (после перехода на вход по почте и Yandex Cloud), всё зелёное:

   | Набор | Команда | Результат |
   |---|---|---|
   | Приложение (Flutter) | `flutter test` | 149 / 149 |
   | Функции (эмулятор Firebase) | `cd firebase/tests` → `npm run test:functions` | 62 / 62 |
   | Функции через переходник Yandex | `cd firebase/tests` → `npm run test:yandex` | 70 / 70 |
   | Функции через переходник Netlify (15.10.2026) | `cd firebase/tests` → `npm run test:netlify` | 74 / 74 |
   | Security Rules | `cd firebase/tests` → `npm test` | 46 / 46 |
   | Анализатор | `flutter analyze` | без замечаний |
   | Релизная сборка | `flutter build apk --release` | собирается |

2. **Ручная проверка на телефонах после деплоя.** Нужна для того, что эмулятор
   проверить не может: настоящие письма, push, внешний вид на реальном экране.

## 1. Запись и отмена: пограничные случаи (ТЗ 3.1)

| Сценарий | Ожидается | Автотест | Вручную |
|---|---|---|---|
| Отмена **ровно за 3 часа** | Отказ «Отмена уже недоступна…» | `граница: ровно за 3 часа — уже нельзя, за 3 ч 2 мин — ещё можно` | Тренер ставит тренировку на «сейчас + 3 ч 1 мин», клиент записывается, ждёт 2 минуты, пробует отменить. Отмена недоступна, значок (i): «Отмена уже недоступна…» |
| Отмена раньше 3 часов | Тренировка вернулась, место свободно | `больше чем за 3 часа: возврат…` | Счётчик «осталось N» вырос на 1 |
| **0 свободных мест** | Отказ `full`, ничего не списано | `нет мест`, `последнее место при одновременной записи получает ровно один` | Тренер ставит 1 место, два клиента жмут «Записаться» одновременно. Запишется ровно один |
| **Замороженный абонемент** | Отказ `frozen` | `идёт заморозка` | Кнопка «Записаться» неактивна, (i): «идёт заморозка» |
| **0 тренировок на счету** | Отказ `no_trainings_left` | `тренировки на абонементе закончились` | Кнопка неактивна, (i) объясняет |
| Без абонемента / истёк / позже срока | Отказ с причиной | `без абонемента`, `абонемент истёк по сроку`, `тренировка позже окончания абонемента` | — |
| Дважды на одну тренировку | Второй раз отказ | `дважды на одну тренировку — нельзя` | — |

## 2. Заморозка (ТЗ 5)

| Сценарий | Автотест | Вручную |
|---|---|---|
| В пределах лимита: срок сдвигается на N дней | `в пределах лимита: с сегодня, срок сдвигается…` | Дата «по …» в абонементе сдвинулась |
| **Повторно в том же периоде** — отказ, даже если использованы не все дни | `один раз за период, даже частично использованная` | Кнопка заморозки после использования недоступна |
| **Больше лимита тренера** — отказ; лимит 0 — заморозки нет | `не больше лимита тренера; лимит 0 — заморозки нет` | Степпер не даёт выбрать больше лимита |
| После продления заморозка снова доступна | `новая запись, старая в истории, заморозка снова доступна` | — |

## 3. Тренер меняет или отменяет тренировку с записанными (ТЗ 3.2)

| Сценарий | Автотест | Вручную |
|---|---|---|
| Отмена: всем записанным тренировка вернулась, ячейка пустая | `всем записанным — возврат; для тренера ячейка снова пустая` | У клиента в ячейке «Отменено», счётчик +1, **пришёл push** |
| Смена времени: у записей новое время, уведомление | `смена времени: у записей новое время, уведомление записанным`; `изменение времени — с датой и строкой для перехода` | Push приходит; тап по нему открывает окно этой тренировки |
| Мест меньше, чем записано, — нельзя | `мест не меньше, чем записано…` | Текст ошибки с числом записанных |
| Только места — без уведомлений | `только места — уведомлений нет` | — |

## 4. «Мусорка»: удаление клиента с тренировки (ТЗ 3.2)

| Проверка | Автотест | Вручную |
|---|---|---|
| Тренировка вернулась клиенту, место освободилось | `возврат тренировки, место свободно, записаться снова нельзя` | Счётчик мест у тренера −1 |
| Повторно записаться **на эту же** тренировку нельзя, на другие — можно | то же | (i) у клиента: «Тренер отменил вашу запись на эту тренировку — записаться на неё снова нельзя» |
| Клиенту пришло уведомление | `отмена тренировки и удаление с тренировки` | Push + запись в истории под колокольчиком |
| Клиент не может удалять других | `клиент не может удалять других` | — |

## 5. Истечение срока и сгорание (ТЗ 5 п. 3, 8.5)

| Проверка | Автотест | Вручную |
|---|---|---|
| Прошёл последний день: `trainingsLeft → 0`, `burnedTrainings`, `expiredAt` | `истёкший: тренировки сгорают…; повтор — без изменений` | На следующее утро после конца тестового абонемента: в приложении «Абонемент истёк», пришёл push |
| В последний день абонемент ещё действует | `последний день абонемента — сегодня: ещё действует` | — |
| Напоминание «скоро закончится» и «осталась 1» — по одному разу | `скоро закончится и истёк…`, `осталась 1 тренировка — один раз за период` | — |
| Плановая задача в облаке запускается | `таймеры Yandex Cloud` (yandex.test.mjs) | Yandex Cloud → Cloud Functions → Триггеры → `jf-expire-daily`: запуск около 00:05 МСК; логи функции |

Быстрая ручная проверка сгорания без ожидания ночи: тренер оформляет тестовому клиенту
абонемент, который заканчивается **вчера**, нельзя (функция не даст — `ends_in_past`).
Поэтому: оформить абонемент, заканчивающийся **сегодня**, а на следующий день посмотреть
результат. Либо в Console поправить у тестового абонемента `endDate` на вчерашний день
и запустить задачу вручную (инструкция, раздел 3.3).

## 6. Обход Cloud Functions напрямую в Firestore (ТЗ 8)

Все сценарии закрыты автотестами правил. Правила проверяются тем же файлом,
который деплоится, так что результат переносится в облако один в один.

| Попытка клиента | Автотест |
|---|---|
| Сделать себя тренером или админом, удалить профиль | `клиент не может поменять себе роль, флаг админа или удалить профиль`, `регистрация: нельзя назначить себе тренера или админа` |
| Накрутить себе тренировки или дни абонемента | `клиент не может накрутить себе тренировки или дни` |
| Накрутить места в тренировке | `клиент не может накрутить места` |
| Записаться/отменить, минуя функцию | `записаться или отменить напрямую нельзя — только функция` |
| Одобрить свою заявку | `одобрить напрямую не может никто — только функция` |
| Читать чужие профили, абонементы, записи | `клиент читает свой профиль, но не чужой`, `клиент видит только свои абонементы`, `клиент видит свою запись, но не чужую` |
| Писать в справочники и настройки | `читают зарегистрированные, пишет никто` |
| Неописанные коллекции | `неописанные коллекции закрыты` |

**После деплоя одна живая проверка:** Console → Firestore → Rules → **Rules Playground**.
Выбрать «Authenticated», указать uid любого клиента и `email_verified: true`, операцию `update` на
`subscriptions/<его абонемент>` с полем `trainingsLeft: 99`. Ожидается **Denied**.
Так видно, что в облаке действуют именно эти правила, а не тестовые «разрешить всё».

## 7. Темы оформления на реальном устройстве (ТЗ 11)

Только вручную, на Android и на iPhone:

- [ ] «Светлая», «Тёмная», «Как в системе» — переключаются сразу, выбор сохраняется после перезапуска.
- [ ] «Как в системе» следует за сменой темы в настройках телефона без перезапуска.
- [ ] Календарь, окна тренировки, абонемент, баннеры, цветок месяца читаются в обеих темах.
- [ ] Системная панель (часы, батарея) видна на обоих фонах.
- [ ] Крупный системный шрифт: подписи в календаре не обрезаются.

## 8. Только на реальных телефонах

- [ ] Регистрация: письмо о подтверждении приходит (в т. ч. на mail.ru / Яндекс — проверить «Спам»); после перехода по ссылке и возврата приложение само пускает дальше.
- [ ] Без подтверждения почты дальше экрана «Подтвердите почту» не пройти.
- [ ] «Забыли пароль?» → письмо → новый пароль → вход.
- [ ] Регистрация с заявкой в тренеры → push администратору.
- [ ] Одобрение заявки → push заявителю, экран сменился на тренерский без перезапуска.
- [ ] Push приходит, когда приложение закрыто, свёрнуто и открыто (при открытом — баннер).
- [ ] Выход из аккаунта: push этому пользователю на этот телефон больше не приходят.
- [ ] Первое действие утром (запись) — ответ за 1–3 с («холодный старт» функции), дальше быстрее.

## Как выкатывать: сначала малая группа

1. **Неделя 1 — «внутренний круг».** Вы (администратор), один тренер и 2–3 клиента,
   которым можно объяснить, что это проверка. Прогнать разделы 1–8 этого списка
   на их телефонах: хотя бы один Android и один iPhone. Первые дни каждое утро
   смотреть логи функций (инструкция, раздел «Логи»).
2. **Проверить ночные задачи.** Хотя бы одна ночь со сгоранием тестового абонемента
   и одно 1-е число месяца (смена цветка) либо ручной запуск задачи (инструкция, раздел 3.3).
3. **Неделя 2 — все.** Раздать приложение остальным ~15 клиентам. Тренер оформляет
   им абонементы в приложении. Бюджетное оповещение в Google Cloud уже должно стоять.
4. Тестовых клиентов после проверки удалить (инструкция, раздел «Удаление пользователя»)
   либо оставить как есть, если это реальные люди.
