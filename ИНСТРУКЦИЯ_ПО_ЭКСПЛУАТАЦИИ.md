# Jumping Fitness — инструкция по развёртыванию и эксплуатации

Для кого: для вас как администратора и разработчика приложения. Знание Firebase
и Yandex Cloud не предполагается: каждое действие расписано по шагам.

Документ из трёх частей:

- **Часть 1. Первый запуск.** Один раз: подключить Firebase и Yandex Cloud, выложить
  сервер, собрать приложение, назначить себя администратором.
- **Часть 2. Проверка и раздача пользователям.**
- **Часть 3. Повседневная работа.** Структура проекта, мониторинг, типовые операции,
  обновления, расходы.

> **Как устроено приложение.** Телефон только показывает данные и отправляет просьбы
> («записать меня»). Решения принимает сервер — функции в **Yandex Cloud**. Данные,
> вход и push-уведомления — в **Firebase** на бесплатном тарифе Spark: база
> **Firestore**, вход по почте и паролю (**Authentication**), push (**Cloud Messaging**).
> **Security Rules** Firestore не дают никому писать в базу в обход сервера.
> Сервер и правила обновляются без переустановки приложения на телефонах.
>
> ```
> Телефон ──вход, чтение──────────────▶ Firebase (Auth, Firestore, push)
>    │                                        ▲
>    └──действия──▶ Yandex API Gateway ──▶ функция Yandex ──(ключ сервисного аккаунта)
> ```

### Отличия от исходного ТЗ (согласованы 27.09.2026)

- **Вход по почте и паролю** с обязательным подтверждением почты вместо входа по SMS
  (ТЗ 2). Телефон указывается при регистрации — для связи тренера с клиентом.
  Причина: SMS на российские номера через Firebase ненадёжны и требуют тарифа Blaze.
- **Серверная логика — в Yandex Cloud Functions**, а не в Firebase Cloud Functions
  (ТЗ 10). Код функций тот же. Причина: Google Cloud не принимает новых клиентов из
  России, тариф Blaze не оплатить. Firebase остаётся на бесплатном тарифе Spark.
- **iPhone — веб-версия** (тот же код Flutter, на экране «Домой») вместо приложения из
  App Store/TestFlight: без аккаунта Apple Developer ($99/год). Android — APK.

## Часть 1. Первый запуск

### 1.0. Что понадобится

| Что | Зачем | Стоимость |
|---|---|---|
| Google-аккаунт | Владелец проекта Firebase | бесплатно |
| Аккаунт Яндекса и платёжный аккаунт Yandex Cloud | Серверные функции; оплата российской картой | в пределах бесплатных объёмов ≈ 0 ₽ (раздел 3.6) |
| Компьютер с Windows (этот) | Сервер и Android-сборка | — |
| Codemagic + GitHub | Только для нативного iOS (1.12) | бесплатные минуты сборки в месяц |
| Apple Developer Program | Только для нативного iOS-приложения (1.12). Для веб-версии (1.11) не нужен | $99 в год — **необязательно** |
| Google Play Console | Только если публиковать в Google Play (не обязательно, см. 1.9) | $25 один раз |

Программы на компьютере (Flutter, Android SDK, Node.js, Java уже стоят):

```bash
npm install -g firebase-tools
```

```bash
dart pub global activate flutterfire_cli
```

Yandex Cloud CLI — в **PowerShell** (не в cmd):

```bash
iex (New-Object System.Net.WebClient).DownloadString('https://storage.yandexcloud.net/yandexcloud-yc/install.ps1')
```

Затем в новом окне терминала: `firebase login` (вход Google-аккаунтом) и `yc init`
(OAuth-токен по ссылке, выбрать облако и каталог `default`).

### 1.1. Проект Firebase (тариф Spark, без карты)

1. https://console.firebase.google.com → **Create a project**. ID проекта —
   `jumpingfitness` (дальше — `<ID-проекта>`). Google Analytics не нужен.
2. **Build → Firestore Database → Create database**: Location **`europe-west3
   (Frankfurt)`**, режим **Production**. Расположение потом не меняется.
3. **Build → Authentication → Get started → Sign-in method → Email/Password →
   Enable → Save**. Второй переключатель («Email link») не нужен.
4. Там же, **Templates** (шаблоны писем): язык писем задаёт приложение (русский).
   По желанию поменяйте имя отправителя на «Jumping Fitness».

### 1.2. Подключить приложение к проекту

Из корня проекта (`E:\MyOwnApps\Jumping Fitness`):

```bash
dart pub global run flutterfire_cli:flutterfire configure --project=jumpingfitness --platforms=android --yes
```

Команда регистрирует Android-приложение в Firebase и создаёт `lib/firebase_options.dart`
и `android/app/google-services.json`. **Уже выполнено 27.09.2026.** iPhone — отдельно на Mac (1.11).

> Эти файлы секретом не являются — они есть внутри любого установленного приложения;
> данные защищают Security Rules.

### 1.3. Правила и индексы Firestore

```bash
firebase deploy --only firestore:rules,firestore:indexes
```

(проект по умолчанию задан в `.firebaserc`). Проверка: Console → Firestore → **Rules** —
там текст из `firestore.rules`.

### 1.4. Ключ сервисного аккаунта Firebase

Функциям в Yandex нужен ключ, чтобы работать с базой и отправлять push.

1. Firebase Console → ⚙ **Project settings → Service accounts → Generate new private key**.
2. Сохраните файл **вне проекта**, например `E:\keys\jf-admin.json`.
3. Ключ даёт полный доступ к базе: никому не пересылайте. После шагов 1.5 и 1.6 он
   хранится в секрете Yandex Lockbox; файл можно удалить (или хранить в надёжном месте
   на случай переустановки).

### 1.5. Выложить сервер в Yandex Cloud

```bash
cd functions; npm run deploy:yc -- --key E:\keys\jf-admin.json
```

Скрипт (повторный запуск безопасен) создаёт в каталоге Yandex Cloud:

| Что | Зачем |
|---|---|
| Сервисный аккаунт `jf-functions` | Функция читает секрет, шлюз и таймеры вызывают функцию |
| Секрет Lockbox `firebase-service-account` | Ключ Firebase из шага 1.4 |
| Функция `jumping-fitness-api` (Node.js 22) | Вся бизнес-логика. Напрямую из интернета не вызывается |
| API Gateway `jumping-fitness-gateway` | Публичный адрес для приложения. Вход проверяет функция по токену Firebase |
| Таймер `jf-expire-daily` | 00:05 МСК: сгорание тренировок по сроку, напоминания об абонементе |
| Таймер `jf-flowers-daily` | 00:10 МСК: цветок месяца (меняется только в начале месяца) |

В конце скрипт печатает адрес шлюза (`https://….apigw.yandexcloud.net`). Он прописан
в приложении (`lib/services/cloud_functions.dart`, `functionsApiUrl`). Если шлюз
создадут заново и адрес изменится — поправить там или собрать с
`--dart-define=FUNCTIONS_API_URL=<адрес>`.

### 1.6. Загрузить справочники

14 цветков (ТЗ 12) и настройки по умолчанию (`settings/defaults`):

```bash
cd functions; npm run seed -- --project jumpingfitness --key E:\keys\jf-admin.json
```

Ответ: `Готово (проект jumpingfitness): цветков — 14. settings/defaults записан.`
Повторный запуск безопасен: ваши правки настроек в Console не затрутся
(перезаписать из файла — `--force-settings`).

### 1.7. Ключ подписи Android

Каждое Android-приложение подписано ключом. **Обновление встанет поверх старой версии,
только если подписано тем же ключом.** Потеряете ключ — всем придётся удалить приложение
и поставить заново. Сделайте один раз и сохраните копию вместе с паролем.

```bash
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkey -v -keystore E:\keys\jumping-fitness-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

Файл `android/key.properties` (он в `.gitignore`):

```properties
storePassword=<пароль>
keyPassword=<пароль>
keyAlias=upload
storeFile=E:/keys/jumping-fitness-upload.jks
```

Без этого файла релиз подписывается отладочным ключом — для проверки годится, для
раздачи нет. Отпечатки SHA для входа по почте **не нужны** (они требовались только для SMS).

### 1.8. Собрать приложение для Android

```bash
flutter build apk --release --split-per-abi
```

В `build\app\outputs\flutter-apk\`: **`app-arm64-v8a-release.apk`** (~25 МБ) — для всех
современных телефонов; `app-armeabi-v7a-release.apk` — для очень старых. Одним файлом
для любых телефонов: `flutter build apk --release` (~77 МБ).

### 1.9. Как раздавать на Android

| | Прямая установка APK | Google Play |
|---|---|---|
| Стоимость | 0 | $25 один раз |
| Подготовка | Нет | Проверка личности, карточка, политика конфиденциальности; **новый личный аккаунт — сначала 14 дней закрытого теста минимум с 12 тестировщиками** |
| Как ставят | Файл в Telegram / на Диске → открыть → разрешить «установку из этого источника» | Из Play Маркета |
| Обновления | Отправить новый файл, ставят поверх | Приходят сами |

**Рекомендация для ~20 человек — прямая установка APK.** Если клиентов станет много —
Google Play (`flutter build appbundle`).

**Постоянная ссылка для скачивания: https://jumpingfitness.web.app/android** — ведёт
на последнюю версию. Сам файл — `JumpingFitness.apk` в последнем релизе на GitHub
(https://github.com/FalkM49/jumping-fitness/releases): бесплатно и без лимита
трафика. Firebase Hosting на тарифе Spark APK не принимает (исполняемые файлы
запрещены).

Новая версия: поднять `version` в pubspec.yaml →
`powershell -ExecutionPolicy Bypass -File tool\publish_apk.ps1` → в открывшейся
странице релиза перетащить `dist\JumpingFitness.apk` (имя не менять) →
**Publish release**. Ссылка сразу начнёт отдавать новую версию.

Что отправить клиентам с Android (можно как есть):

> 1. Откройте на телефоне ссылку https://jumpingfitness.web.app/android — скачается JumpingFitness.apk.
> 2. Откройте скачанный файл. Если телефон спросит — разрешите установку «из этого источника».
> 3. Если Play Защита предупредит «не проверено» — «Подробнее» → «Всё равно установить».
> 4. Откройте Jumping Fitness и зарегистрируйтесь по почте.

### 1.10. Первый вход и назначение администратора

1. Установите APK, нажмите «Впервые здесь? Зарегистрироваться», введите почту и пароль.
2. Откройте письмо (проверьте «Спам»), перейдите по ссылке, вернитесь в приложение
   — оно само увидит подтверждение (или нажмите «Я подтвердил(а) почту»).
3. Укажите ФИО и телефон → «Готово».
4. Firebase Console → **Firestore Database** → `users` → документ с вашим `phone`
   (или найдите свой **User UID** в Authentication по почте) → поле `isAdmin` → **`true`**
   (boolean) → Update. Приложение само переключится на экран тренера со значком
   «Заявки в тренеры».

Это **единственный** способ стать администратором (ТЗ 2). Второго назначают так же;
снять права — `false`.

### 1.11. iPhone — веб-версия (бесплатно, основной способ)

Без аккаунта Apple Developer ($99/год) приложение на iPhone не поставить, поэтому
для iPhone — **веб-версия** того же приложения (тот же код Flutter). Человек открывает
ссылку в Safari и добавляет её на экран «Домой»: появляется иконка, приложение
открывается на весь экран, работают вход, запись и **push-уведомления** (iOS 16.4+).

**Выложить (и после каждого изменения приложения):**

```bash
powershell -ExecutionPolicy Bypass -File tool\build_web.ps1
```

Скрипт собирает с нужными флагами: движок со своего хостинга (`--no-web-resources-cdn`),
карты исходников (`--source-maps`) и версия из `pubspec.yaml` для журнала ошибок.
Сначала проверьте на канале предпросмотра — основной сайт он не трогает:

```bash
firebase hosting:channel:deploy iphone-check --expires 7d
```

```bash
firebase deploy --only hosting
```

Адрес: **https://jumpingfitness.web.app**. Хостинг бесплатный (тариф Spark).
Обновление появляется у всех само при следующем открытии — ничего пересылать не нужно.

**Ключ для веб-push (один раз, рекомендуется):** Firebase Console → Project settings →
Cloud Messaging → **Web Push certificates → Generate key pair** → скопировать ключ
(он не секретный). Он уже прописан в `lib/notifications/push_service.dart`; другой ключ —
при сборке через `--dart-define=WEB_PUSH_VAPID_KEY=<ключ>`.

**Что сказать клиентам с iPhone** (можно переслать как есть):

> 1. Откройте в **Safari** ссылку https://jumpingfitness.web.app
> 2. Нажмите «Поделиться» (квадрат со стрелкой вверх) → **«На экран „Домой“»** → «Добавить».
> 3. Откройте Jumping Fitness **с иконки** на экране, зарегистрируйтесь по почте.
> 4. Нажмите «Включить уведомления» на главном экране и разрешите.

Особенности: push на iPhone приходят, только если приложение открыто с иконки
(не из вкладки Safari); первое открытие — несколько секунд (загружается ~3–5 МБ),
дальше быстро. Тап по уведомлению открывает приложение (без перехода к конкретной
тренировке — это есть только в Android-версии).

Для разработки: `tool\build_web.ps1 -Emulators` и `npm run dev:api`. В режиме
эмуляторов вход в браузере не переживает перезагрузку страницы (Firebase Auth проверяет
сохранённый вход раньше, чем переключается на эмулятор) — в настоящем проекте такого нет.

**Журнал ошибок веб-версии.** Необработанные ошибки, сбои вызовов функций, перезагрузки
вкладки из-за нехватки памяти (`unexpected_reload`) и потеря WebGL приложение присылает
само: Yandex Cloud → Cloud Functions → `jumping-fitness-api` → **Логи**, записи
«Ошибка в приложении: …» (поле `kind`, `errorMessage`, `route`, `userAgent`).

### 1.12. iPhone — нативное приложение через Codemagic (если появится Apple Developer)

Код общий для Android и iOS. iOS-приложение уже зарегистрировано в Firebase
(`firebase_options.dart`), в проекте включены push (`Runner.entitlements`, фоновые
уведомления) и iOS 15 как минимум. Собирает приложение Codemagic на своих Mac и сам
загружает в TestFlight — настройки в `codemagic.yaml`.

**Что нужно:** Apple Developer Program (**$99/год**, https://developer.apple.com/programs/ —
оформление на физлицо, подтверждение 1–2 дня), аккаунт GitHub, аккаунт Codemagic
(вход через GitHub; есть бесплатные минуты сборки на Mac в месяц).

1. **Код на GitHub.** Создайте **приватный** репозиторий (например, `jumping-fitness`)
   и отправьте туда проект — локальный репозиторий уже создан:
   ```bash
   git remote add origin https://github.com/<логин>/jumping-fitness.git
   ```
   ```bash
   git push -u origin main
   ```
2. **Приложение в App Store Connect.** https://appstoreconnect.apple.com → Apps → «+» →
   New App: iOS, название «Jumping Fitness», язык — русский, Bundle ID
   `ru.jumpingfitness.jumpingFitness` (если его нет в списке — developer.apple.com →
   Identifiers → «+» → App IDs, этот Bundle ID, отметить **Push Notifications**), SKU —
   любой, например `jumpingfitness`.
3. **Ключ API для Codemagic.** App Store Connect → Users and Access → **Integrations →
   App Store Connect API** → «+» → роль **App Manager** → скачать `.p8` (скачивается
   один раз!), запомнить Issuer ID и Key ID.
4. **Codemagic.** https://codemagic.io → войти через GitHub → Add application →
   репозиторий `jumping-fitness` → тип **Flutter App (via codemagic.yaml)**.
   Затем Team settings → **Integrations → Developer Portal → Manage keys** → Add key:
   имя **`jumping-fitness-asc`** (ровно так — оно указано в `codemagic.yaml`), Issuer ID,
   Key ID, файл `.p8`.
5. **Push для iPhone.** developer.apple.com → Certificates, IDs & Profiles → **Keys** → «+» →
   *Apple Push Notifications service (APNs)* → скачать `.p8` (один раз!), запомнить Key ID
   и Team ID → Firebase Console → Project settings → **Cloud Messaging** → Apple app
   configuration → **APNs Authentication Key** → загрузить.
6. **Сборка.** Codemagic → приложение → **Start new build** → workflow «iPhone → TestFlight».
   Около 15–25 минут: тесты, подпись (сертификат и профиль Codemagic создаст сам),
   сборка, загрузка в TestFlight.
7. **Раздача.** App Store Connect → приложение → **TestFlight** → группа тестировщиков →
   добавить людей по почте. Они ставят приложение **TestFlight** из App Store и по
   приглашению — Jumping Fitness. Для внешних тестировщиков Apple один раз коротко
   проверяет сборку (обычно до суток).

⚠️ **Сборка в TestFlight работает 90 дней.** Не реже раза в 2–3 месяца запускайте
новую сборку в Codemagic (кнопка — и всё), даже без изменений, иначе приложение
у людей перестанет открываться. Альтернатива TestFlight — Ad Hoc (до 100 iPhone
по UDID, профиль на год), но с ней больше ручной работы.

## Часть 2. Проверка и раздача пользователям

Полный чек-лист: [docs/08_test_checklist.md](docs/08_test_checklist.md).

1. **Неделя 1:** вы, один тренер и 2–3 знакомых клиента (хотя бы один Android и один
   iPhone). Пройти чек-лист; каждое утро смотреть логи функции (3.3).
2. Пережить хотя бы одну ночь со сгоранием тестового абонемента.
3. **Неделя 2:** раздать остальным. Тренер оформляет абонементы в приложении.

Живая проверка правил: Firebase Console → Firestore → Rules → **Rules Playground** →
Authenticated, uid клиента, в Firebase token добавить `"email_verified": true`,
`update` документа `subscriptions/<его абонемент>` с `trainingsLeft: 99` → **Denied**.

### 3.2. Полный доступ для мониторинга

**Firebase** — владелец проекта (Google-аккаунт, создавший его) видит всё. Дать доступ
другому разработчику: Project settings → **Users and permissions** → Add member → **Owner**.

**Yandex Cloud** — владелец облака видит всё. Другому: https://console.yandex.cloud →
облако → **Права доступа** → Назначить роли → `admin` на облако.

| Где | Что там |
|---|---|
| Firebase → **Firestore Database** | Все данные: просмотр и ручная правка любого документа |
| Firebase → **Authentication → Users** | Все аккаунты: почта, uid, дата входа; заблокировать, удалить, сбросить пароль |
| Yandex Cloud → **Cloud Functions → jumping-fitness-api → Логи** | Журнал сервера: ошибки, предупреждения |
| Yandex Cloud → **Cloud Functions → Мониторинг** | Число вызовов, ошибок, время ответа |
| Yandex Cloud → **Cloud Functions → Триггеры** | Ночные задачи: когда запускались |
| Yandex Cloud → **API Gateway** | Публичный адрес, число запросов |
| Yandex Cloud → **Биллинг** | Расходы |
| Firebase → **Crashlytics** | **Не подключён**. Подключить позже можно (пакет `firebase_crashlytics`, это обновление приложения) |

### 3.3. Повседневные операции

**Заявки в тренеры.** В приложении под администратором: значок «Заявки в тренеры»
в шапке → «Одобрить» / «Отклонить». О новой заявке приходит push.

**Пользователь жалуется («не могу записаться», «пропала тренировка»):**

1. Firebase → Authentication → найти по почте → скопировать **User UID**.
2. Firestore → `users/<uid>` → `currentSubscriptionId` → `subscriptions/<id>`: остаток,
   срок, заморозка.
3. Записи: `trainings/<id тренировки>/bookings/<uid>`, поле `status`: `active` — записан,
   `cancelled_by_client` — отменил сам, `removed_by_trainer` — удалил тренер,
   `training_cancelled` — тренировку отменили.
4. Логи: Yandex Cloud → Cloud Functions → `jumping-fitness-api` → **Логи**, фильтр по уровню
   ERROR и времени. Отказ по правилам студии («нет мест», «заморозка») — **не ошибка**,
   клиент видит объяснение под значком (i). Из терминала:

   ```bash
   yc serverless function logs jumping-fitness-api --since 1h
   ```

**Не приходит письмо / забыли пароль.** В приложении «Забыли пароль?». Или Firebase →
Authentication → пользователь → ⋮ → **Reset password** (письмо уйдёт ему). Подтвердить
почту вручную (если письмо так и не дошло): в Authentication этого нет — попросите
проверить «Спам» и нажать «Отправить письмо ещё раз».

**Ночная задача не сработала:** Yandex Cloud → Cloud Functions → Триггеры → проверить
запуски. Запустить вручную из терминала:

```bash
yc serverless function invoke jumping-fitness-api -d '{"messages":[{"details":{"payload":"expireSubscriptionsDaily"}}]}'
```

Повторный запуск ничего не испортит.

**Поменять значения по умолчанию** (время, места, лимит заморозки, 3 часа на отмену):
Firestore → `settings/defaults`. Действует сразу.

**Удалить пользователя:** сначала пусть тренер удалит его «мусоркой» с будущих тренировок;
затем Firebase → Authentication → ⋮ → Delete account и Firestore → `users/<uid>` → Delete.

### 3.4. Ручная правка данных: что можно, чего нельзя

Всё, что можно сделать в приложении, делайте в приложении.

**Можно:** `users/<uid>`: `fullName`, `phone`, `isAdmin`; `settings/defaults` — любые
значения; `flowers/<id>` — тексты; `trainings/<id>`: `capacity` (не меньше `bookedCount`).

**Не трогать** (ведёт сервер):

| Документ | Поля | Почему |
|---|---|---|
| `trainings/<id>` | `bookedCount`, `status`, `startAt`, `slotKey` | Счётчик = число записей `active`; время меняет тренер в приложении (тогда обновятся записи и придут уведомления) |
| `trainings/<id>/bookings/<uid>` | всё | Статус связан со счётом тренировок |
| `calendar_slots/<id>` | всё | Какая тренировка стоит в ячейке |
| `subscriptions/<id>` | `isCurrent`, `trainingsLeft`, `burnedTrainings`, `freeze`, `endDate`, `originalEndDate`, `expiredAt`, `notified` | Взаимосвязаны; меняются продлением у тренера |
| `users/<uid>` | `role`, `currentSubscriptionId`, `monthlyFlower`, `recentFlowerIds` | Роль — одобрением заявки; абонемент — продлением |
| `trainer_requests/<uid>` | `status`, `adminsNotifiedAt` | Решение — через экран заявок |

Самый частый ручной случай — вернуть тренировку: в `subscriptions/<текущий>` увеличить
`trainingsLeft` на 1, больше ничего. Перед правкой — скриншот документа.

### 3.5. Как выпускать обновления

**Сервер и правила — без обновления приложения у людей.** Перед выкладкой прогоните
тесты (`cd firebase/tests`, затем `npm run test:all`).

```bash
cd functions; npm run deploy:yc
```

```bash
firebase deploy --only firestore:rules,firestore:indexes
```

У людей какое-то время живут старые версии приложения: если меняется то, что функции
принимают на вход, старые версии должны продолжать работать.

**Само приложение** (`lib/`, иконка, название, `android/`, `ios/`) — новой сборкой:

1. В `pubspec.yaml` поднять версию: `0.1.0+1` → `0.1.1+2` (число после `+` растёт всегда).
2. `flutter test`, затем `flutter build apk --release --split-per-abi` тем же ключом.
3. Выложить по постоянной ссылке (сборка + загрузка одним скриптом):
   `powershell -ExecutionPolicy Bypass -File tool\publish_apk.ps1`. Сообщить клиентам
   «обновите по ссылке https://jumpingfitness.web.app/android» — ставят **поверх**,
   данные и вход сохраняются.
4. iPhone (веб-версия): `tool\build_web.ps1`, проверка на канале предпросмотра, затем
   `firebase deploy --only hosting` — обновится у всех сама.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| «Приложение ещё не подключено к серверу…» | Нет `lib/firebase_options.dart` от `flutterfire configure` (1.2) — пересобрать |
| «Неверная почта или пароль» | Проверить раскладку; «Забыли пароль?» |
| Письмо о подтверждении не приходит | «Спам»; «Отправить письмо ещё раз» через минуту; проверить адрес («Другая почта») |
| Любое действие: «Не получилось выполнить действие» | Логи функции (3.3). Частые причины: нет секрета с ключом (1.5), неверный адрес шлюза в приложении (1.5) |
| «Сессия истекла. Войдите заново» при каждом действии | Часы телефона сильно сбиты, или ключ в секрете — от другого проекта Firebase |
| Push не приходят на Android | Разрешение на уведомления; энергосбережение для приложения — «Без ограничений» |
| Push не приходят на iPhone | Нет ключа APNs (1.11, п. 2) или capability Push Notifications |
| Ночью тренировки не сгорели | Yandex Cloud → Триггеры → запуски; ручной запуск (3.3) |
| Все видят «Нет доступа» / пустые экраны | Сломаны правила: откатить `firestore.rules` и выложить снова (в Console → Rules есть история версий) |
